# 02 系统架构

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 界面 | HTML / CSS / JS（可引入单文件 Vue，不需要构建工具） | 复用已有原型；Edge 应用模式打开后就像机器屏幕 |
| 后端 | Python 3.10+，Flask | 组员熟悉 Python；Flask 只负责 HTTP，足够轻 |
| 数据库 | SQLite（标准库 sqlite3） | 单文件，不用装数据库服务，拷走就能跑 |
| 支付 | 模拟支付；加分项接支付宝沙箱当面付 | 演示不依赖网络，同时保留真实支付的接口 |
| 机器 | Python 模拟器 | 没有真机；接口与真机驱动一致 |
| 测试 | pytest | 契约测试 + 进度看板 |

依赖只有 `flask` 和 `pytest`（开发用）。

### 和真实饮料机的对应

真实设备分三层：机器里的工控板跑“界面 + 本地服务 + 本地数据库”，下位机控制电机和水泵，云端负责支付、汇总和运营。本项目把前两层合在一台电脑上，用模拟器代替下位机，不做自建云端。支付宝是唯一用到的外部云服务。

## 3. 模块依赖

```
web.api ──► OrderService ──► IngredientService ──► InventoryService ──► Repository
                │     │              │                                     ▲
                │     │              └──► StatsService ────────────────────┤
                │     ├──► InventoryService                                │
                │     ├──► MachineDriver                                   │
                │     ├──► PaymentGateway                                  │
                │     └──► Repository ─────────────────────────────────────┘
```

规则：

1. **只依赖接口，不依赖实现**。构造函数参数的类型都是 `interfaces.py` 里的抽象类；具体用哪个实现由 `wiring.py` 决定。
2. **只有 Repository 能碰数据库**。其他模块不写 SQL。
3. **下层不知道上层**。`model` 不导入任何业务模块；`maintenance` 不导入 `sales`；没有模块导入 `web`。
4. **业务规则不写在 web 层和前端**。价格、能否售卖、状态流转都由后端决定，前端只展示。
5. 所有模块只抛 `DrinkError`，web 层统一转成 HTTP 错误。

## 4. 运行机制：轮询驱动

订单状态不靠后台线程推进，而是在查询时推进：

```
前端每秒 GET /api/orders/<id>
   └─ OrderService.get_order()
        ├─ 待付款：问支付渠道“付了吗？”→ 付了就启动制作
        ├─ 制作中：问机器“做好了吗？”→ 好了就完成
        └─ 返回最新订单
```

选这种方式的原因：

- 没有后台线程，测试时用 FakeClock 快进时间就能复现任何场景，结果确定；
- 和支付宝“主动查询”的接入方式一致，不需要公网回调地址；
- 维护页查订单列表时也会推进活动订单（`list_orders` 的约定），所以没人看点单页时状态也不会停滞。

代价是点单页关掉后，订单要等下次有人查询才会推进。单机单顾客场景下可以接受，文档里说明即可。

## 5. 参考实现与正式实现

每个接口都有两种实现：

| | 参考实现 `drink/testing/reference.py` | 正式实现（各人的文件） |
|---|---|---|
| 谁写 | 已提供 | 各负责人 |
| 数据 | 内存，重启即清空 | SQLite，重启不丢 |
| 用途 | 证明测试正确；让程序在大家写完之前就能跑；接口有疑问时可以参考 | 最终交付 |

启动时可以逐个替换：

```
python run.py                            # 全部参考实现：A 现在就能开发界面
python run.py --real inventory,machine   # C 写完库存和机器后，在完整程序里看效果
python run.py --real all                 # 最终演示
```
