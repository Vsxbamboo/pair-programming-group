# 07 支付宝沙箱配置

代码已经写好（`drink/sales/payment_alipay.py`，离线测试 `tests/contract/test_alipay.py`）。真机联调需要**一个人**用自己的支付宝账号在开放平台开通沙箱，大约 15 分钟。沙箱不收费、不需要营业执照，钱都是假的。

> 不想接支付宝也完全没问题：默认的模拟支付已经能完整演示，手机扫码会打开“一杯 · 演示收银台”。

## 1. 开通沙箱应用（需要你登录）

1. 浏览器打开 <https://open.alipay.com>，用自己的支付宝扫码登录（首次登录需要按提示完成开发者入驻，选“个人开发者”即可）。
2. 进入“控制台 → 沙箱”（或直接打开 <https://open.alipay.com/develop/sandbox/app>）。
3. 记下页面上的 **APPID**（一串以 `9021` 开头的数字）。

## 2. 生成并上传密钥

1. 在项目目录运行：

   ```bash
   pip install -r requirements-alipay.txt
   python tools/gen_alipay_keys.py
   ```

   > 如果你用的是 MSYS2 自带的 Python，pip 装不了 `cryptography`（没有现成安装包，会尝试从源码编译）。
   > 可以在 MSYS2 终端里运行 `pacman -S mingw-w64-x86_64-python-cryptography`，再用
   > `python -m venv --system-site-packages .venv` 重建虚拟环境；或者改用 python.org 下载的官方 Python。

   会生成 `keys/app_private_key.pem`（应用私钥，**只留在本机**）和 `keys/app_public_key.txt`，并把应用公钥打印出来。
2. 回到沙箱页面，找到“接口加签方式 → 自定义密钥 → 公钥模式 → 设置”，把打印出来的那一整行**应用公钥**粘贴进去保存。
3. 保存后页面会显示 **支付宝公钥**。把它复制下来，存成 `keys/alipay_public_key.txt`（一整行即可）。

> `keys/` 和 `alipay.json` 已经在 `.gitignore` 里，不会被提交。仓库是公开的，**千万不要把私钥发到群里或提交到 git**。

## 3. 填配置

把 `alipay.example.json` 复制成 `alipay.json`，只需要改 `app_id`：

```json
{
  "app_id": "9021000xxxxxxxxx",
  "private_key_path": "keys/app_private_key.pem",
  "alipay_public_key_path": "keys/alipay_public_key.txt",
  "gateway": "https://openapi-sandbox.dl.alipaydev.com/gateway.do"
}
```

也可以用环境变量代替（优先级更高）：`ALIPAY_APP_ID`、`ALIPAY_PRIVATE_KEY_PATH`、`ALIPAY_PUBLIC_KEY_PATH`、`ALIPAY_GATEWAY`。

## 4. 准备付款用的手机

1. 在沙箱页面的“沙箱工具”里下载**沙箱版支付宝**（安卓）。它和正式版支付宝是两个 App，可以同时装。
2. 在“沙箱账号”里找到**买家账号**和登录密码、支付密码，用它登录沙箱版支付宝。

## 5. 启动

```bash
python run.py --payment alipay --open
```

下单后点单页会显示支付宝二维码，用沙箱版支付宝扫码付款，几秒后点单页自动进入“正在为你现调”。

维护台的退款按钮会调用 `alipay.trade.refund`，退款会退回到沙箱买家账户。

## 6. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动时提示“支付宝配置有误” | `alipay.json` 不存在或路径不对；按第 3 步检查 |
| 下单时提示“支付宝返回验签失败” | `alipay_public_key.txt` 填成了“应用公钥”；应该是上传后页面给出的“支付宝公钥” |
| 下单时提示 `invalid-signature` / `isv.invalid-signature` | 上传的应用公钥和本地私钥不是一对；重新运行 `gen_alipay_keys.py --force` 并重新上传 |
| 提示 `isv.invalid-app-id` | APPID 填错，或把正式环境的 APPID 用在了沙箱网关 |
| 扫码后提示“二维码已失效” | 订单 2 分钟内没付款已自动关闭，重新下单 |
| 付款成功但点单页没反应 | 点单页靠每秒查询支付宝，确认电脑能访问外网；看终端里有没有 `PAYMENT_ERROR` |

## 7. 实现说明（给 B）

- 用的是“当面付 · 扫码支付”：`alipay.trade.precreate` 生成二维码，`alipay.trade.query` 轮询结果。没有用 `notify_url` 异步通知，所以不需要公网服务器。
- 请求用 RSA2（SHA256withRSA）签名，响应用支付宝公钥验签；网络、签名、业务错误统一转成 `PAYMENT_ERROR`。
- 顾客还没扫码时，支付宝查不到这笔交易（`ACQ.TRADE_NOT_EXIST`），按“等待付款”处理；超时后由订单服务关闭。
- 离线测试用一个假网关模拟支付宝的签名和返回，覆盖下单、查询、关单、退款、验签失败、网络错误和接入完整下单流程。
