# 04 接口契约

> 版本：v0.3（2026-11-10）。每次修改接口都把版本号加一，并在文末“变更记录”写一行。

接口是全组的“合同”。在边界内怎么实现由负责人自由决定；**改边界（方法签名、行为约定、URL、JSON 字段）必须全组同意**，并同时修改：本文、对应的 `interfaces.py` 文档字符串、契约测试。

## 1. 模块之间：Python 接口

完整约定以代码中的文档字符串为准，下表是索引。

### 1.1 Repository（D）· `drink/model/repository.py`

| 方法 | 返回 | 要点 |
|---|---|---|
| `initialize(materials, menu_items, initial_stock)` | None | 建表；没有数据时写入初始数据；可重复调用 |
| `list_materials()` / `list_menu_items()` | list | 按初始化顺序 |
| `get_menu_item(id)` | MenuItem \| None | |
| `list_stock()` / `get_stock(id)` | StockLevel | 不存在 → NOT_FOUND |
| `apply_stock_changes(deltas)` | None | 原子；结果 < 0 → OUT_OF_STOCK（`missing` 排序）；未知原料 → NOT_FOUND |
| `save_order(order)` / `get_order(id)` | — / Order \| None | 读回必须与存入的对象完全相等 |
| `list_orders(machine_id, statuses, since_ms, until_ms, limit)` | list[Order] | 最新在前；since 含、until 不含 |
| `add_restock(...)` / `list_restocks(limit)` | RestockRecord | 只记录不改库存；最新在前 |

### 1.2 IngredientService（B）· `drink/sales/interfaces.py`

| 方法 | 返回 | 要点 |
|---|---|---|
| `get_menu()` | Menu | 含每项 `available`（规则见 03 §3.3） |
| `validate(recipe)` | None | 不合法 → INVALID_RECIPE；不看库存 |
| `quote(recipe)` | Quote | 明细：基底、加料（按选择顺序）、大杯加价 |
| `consumption_of(recipe)` | dict | 换算规则见 03 §3.3 |
| `recommend(limit=3)` | list[Recipe] | 先销量后预设，去重，只推荐能做的 |

### 1.3 OrderService（B）

| 方法 | 返回 | 要点 |
|---|---|---|
| `create_order(recipe)` | Order | 检查顺序见 03 §4.3；返回 AWAITING_PAYMENT |
| `get_order(id)` | Order | 查询并推进状态（03 §4.2） |
| `cancel_order(id)` | Order | 只能取消 AWAITING_PAYMENT，否则 INVALID_STATE |
| `list_orders(status, limit)` | list[Order] | 本机订单，先推进活动订单 |
| `refund_order(id, operator)` | Order | 只能退 PRODUCTION_FAILED |

### 1.4 PaymentGateway（B）

`create(order_id, amount_fen, subject) → PaymentInfo`（幂等）· `query(order_id) → PaymentStatus` · `close(order_id)`（已成功的不受影响）· `refund(order_id, amount_fen)`（只退 SUCCESS）。

### 1.5 InventoryService（C）· `drink/maintenance/interfaces.py`

`list_stock()` · `check(consumption) → list[str]` · `consume(consumption, order_id)`（原子）· `restock(material_id, quantity, operator) → StockLevel` · `list_restocks(limit)`。

### 1.6 StatsService（C）

`summary(machine_id=None, since_ms=None, until_ms=None) → SalesSummary` · `top_recipes(limit=3) → list[ComboCount]`。

### 1.7 MachineDriver（C）

`machine_id` · `status() → MachineState` · `start_job(order_id, consumption)`（异步、幂等）· `job_status(order_id) → JobStatus` · `clear_fault(code=None) → MachineState`。模拟器另有 `inject_fault(code)`（演示用）。

### 1.8 构造参数（wiring.py 按此创建，不要改）

```python
SqliteRepository(db_path)
IngredientServiceImpl(repo, inventory, stats)
OrderServiceImpl(machine_id, repo, ingredient, inventory, machine, payment, clock)
InventoryServiceImpl(repo, clock)
StatsServiceImpl(repo, clock)
MachineSimulator(machine_id, clock, job_ms=6000)
```

## 2. JSON 约定

- 字段名与 Python 实体字段一致（snake_case）。
- 枚举为字符串：`"M"`、`"ICED"`、`"HALF"`、`"AWAITING_PAYMENT"`……
- 金额为整数分，时间为 epoch 毫秒。
- tuple 变成数组；`null` 表示无。
- dict 的整数键会变成字符串：`by_hour` 是 `{"9": 3, "15": 2}`。
- 实体 → JSON 统一用 `drink.model.serialize.to_jsonable`；Recipe 的解析用 `recipe_from_dict`。

**Recipe**（请求里提交的配方，后 4 个字段可省略，省略时取默认值）

```json
{"base_id": "milk_tea", "addon_ids": ["pearl"], "size": "M", "temperature": "ICED", "sugar": "HALF"}
```

**错误**

```json
HTTP 409
{"error": {"code": "OUT_OF_STOCK", "message": "部分原料不足，请换一种配方", "details": {"missing": ["coconut"]}}}
```

## 3. 前后端之间：HTTP 接口（A 实现于 `drink/web/api.py`，前端封装于 `static/js/api.js`）

### 3.1 顾客

| 方法 | 路径 | 请求 | 成功响应 |
|---|---|---|---|
| GET | `/api/config` | — | `{"demo": true, "machine_id": "M001", "payment_method": "mock", "pay_base_url": "http://192.168.1.5:3000"}`；前端据此决定是否显示演示按钮、演示二维码指向哪里 |
| GET | `/api/qr.svg?text=...` | — | 把 `text`（≤600 字）画成二维码 SVG。模拟支付时 text 为 `{pay_base_url}/pay/{订单号}`，支付宝时为 `payment.qr_content` |
| GET | `/api/menu` | — | Menu |
| GET | `/api/recommendations?limit=3` | — | Recipe[] |
| POST | `/api/quotes` | Recipe | Quote |
| POST | `/api/orders` | Recipe | **201** Order |
| GET | `/api/orders/<id>` | — | Order（同时推进状态，前端每秒轮询） |
| GET | `/api/orders/<id>/progress` | — | JobStatus（仅 MAKING 之后有意义） |
| POST | `/api/orders/<id>/cancel` | — | Order |
| GET | `/api/machine` | — | MachineState |

### 3.2 维护人员

| 方法 | 路径 | 请求 | 成功响应 |
|---|---|---|---|
| GET | `/api/admin/stock` | — | StockLevel[]（含 `status`） |
| POST | `/api/admin/restock` | `{"material_id", "quantity", "operator"}` | StockLevel |
| GET | `/api/admin/restocks?limit=50` | — | RestockRecord[] |
| GET | `/api/admin/orders?status=PRODUCTION_FAILED&limit=50` | — | Order[] |
| POST | `/api/admin/orders/<id>/refund` | `{"operator"}` | Order |
| POST | `/api/admin/machine/clear-fault` | `{"code"}` 或 `{}`（清全部） | MachineState |
| GET | `/api/admin/stats?machine_id=&since_ms=&until_ms=` | — | SalesSummary |

### 3.3 演示（`python run.py --no-demo` 时不存在）

页面 `GET /pay/<订单号>`：手机扫演示二维码后打开的“演示收银台”，调用下表的接口完成模拟付款。

| 方法 | 路径 | 请求 | 作用 |
|---|---|---|---|
| POST | `/api/dev/payments/<id>/succeed` | — | 模拟顾客扫码付款成功，返回推进后的 Order |
| POST | `/api/dev/payments/<id>/close` | — | 模拟支付失败 / 被关闭 |
| POST | `/api/dev/machine/faults` | `{"code": "CUP_JAM"}` | 注入故障，返回 MachineState |

## 4. 修改流程

1. 在群里提出：改什么、为什么、影响谁；
2. 相关负责人同意后，由提出人同时修改本文、`interfaces.py`、契约测试；
3. 跑一遍 `pytest -k reference`，参考实现必须仍然全绿（必要时同步修改参考实现）；
4. 提交时在说明里写清楚“接口变更”。
