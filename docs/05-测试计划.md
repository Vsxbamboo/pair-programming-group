# 05 测试计划

## 1. 思路：先写测试，再写实现

每个接口的验收标准已经写成测试（契约测试）。每个契约测试都会跑两遍：

| 参数 | 被测对象 | 应该是 |
|---|---|---|
| `[reference]` | 参考实现 `drink/testing/reference.py` | **永远全绿**。若变红，说明测试或参考实现写错了 |
| `[real]` | 你的正式实现 | 开始时全部“未实现”，写完一个方法就绿一批 |

测试结束时会打印进度表：

```
==================== 各负责人进度（real = 你的正式实现；reference = 参考实现，应全绿） ====================
负责人            对象         通过  未实现  失败  跳过  合计
A GUI             real           26       0     0     0    26  √ 完成
B 销售+食材       real            0      48     0     1    49
C 数据+机器维护   real            0      35     0     0    35
D 数据结构        real            0      18     0     0    18
全组 集成         real            0       1     0     0     1
```

- **未实现**：测试撞上了 `NotImplementedError`，还没写；
- **失败**：已经写了，但行为不符合约定，这才需要修。

## 2. 怎么跑

```bash
pip install -r requirements-dev.txt

pytest                                       # 全部，看进度表
pytest tests/contract/test_inventory.py      # 只看一个模块
pytest -k real                               # 只跑正式实现
pytest tests/contract/test_order.py -k "real and TestCancel"   # 只跑某一组
pytest -x --tb=long -k real                  # 遇到第一个失败就停，打印完整报错
```

测试不碰你的 `data/drink.db`：每个测试用临时目录里的新数据库和 FakeClock。

## 3. 测试分层

| 层 | 位置 | 内容 | 负责人 |
|---|---|---|---|
| 契约测试 | `tests/contract/` | 每个接口的行为约定 | 各模块负责人（维护测试，让 real 变绿） |
| 接口测试 | `tests/api/` | URL、请求/响应 JSON、错误映射；后端用参考实现 | A |
| 集成测试 | `tests/integration/` | 一天营业的完整流程；`[real]` 为全部正式实现 | D |
| 界面验收 | 本文 §5 | 手工按清单点一遍 | A（全组参与） |
